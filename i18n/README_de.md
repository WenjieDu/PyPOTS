PyPOTS (ausgesprochen „Pie Pots“) ist eine Open-Source-Python-Toolbox zur Zeitreihenanalyse mit **über 50 Modellen und Methoden mit einheitlichen APIs** für Imputation, Prognose, Klassifikation, Clustering, Anomalieerkennung und Repräsentationslernen. Sie wurde für reale Zeitreihen entwickelt, auch für solche mit fehlenden Werten.

Eine Zeitreihe ist nicht das zugrunde liegende System selbst, sondern eine Sammlung von Beobachtungen dieses Systems. Aufgrund der Grenzen von Messung und Abtastung sind reale Zeitreihen grundsätzlich partielle Beobachtungen: Gemessene Variablen erfassen nur bestimmte Aspekte des Systems, Beobachtungen erfolgen in diskreten und möglicherweise unregelmäßigen Abständen, und Messwerte können fehlen.

**Nicht beobachtet bedeutet nicht zwangsläufig nicht existent. Partielle Beobachtung ist die Regel, nicht die Ausnahme.**

Wir verstehen reale Zeitreihen als **partiell beobachtete Zeitreihen (Partially-Observed Time Series, POTS)**. Aus dieser Perspektive besteht Zeitreihenmodellierung im Wesentlichen darin, das zugrunde liegende System und seine Dynamik aus partiellen Beobachtungen zu lernen. PyPOTS baut auf dieser Philosophie auf, um eine einheitliche Analyse realer Zeitreihen zu ermöglichen.

## ❖ Hauptfunktionen

- **Unterstützung mehrerer Aufgaben:** Imputation, Prognose, Klassifikation, Clustering, Anomalieerkennung und Repräsentationslernen in einer Toolbox.
- **Native Unterstützung fehlender Werte:** Modelle, die fehlende Werte berücksichtigen, können ohne vorherige Imputation direkt aus unvollständigen Zeitreihen lernen.
- **Einheitliche APIs:** Konsistente Trainings- und Vorhersageschnittstellen erleichtern Experimente und Modellvergleiche.
- **Umfangreicher Modellkatalog:** Über 50 Modelle und Methoden, darunter klassische Ansätze, Deep Learning, LLM-basierte Modelle und Zeitreihen-Basismodelle (TSFM).
- **<a href="https://landscape.pytorch.org/?item=modeling--specialized--pypots"><img src="https://pypots.com/figs/misc/pytorch.svg" width="26px" align="center">PyTorch Ecosystem</a>:** PyPOTS basiert auf PyTorch und ist in der PyTorch Landscape gelistet.
- **Hardwarebeschleunigung:** CPU, NVIDIA-CUDA-GPUs und Ascend-NPUs; Training auf mehreren Geräten mit PyTorch DistributedDataParallel (DDP), CUDA DataParallel und automatische gemischte Genauigkeit für unterstützte Modelle. Einrichtung und Einschränkungen siehe [Beschleunigungsleitfaden](https://docs.pypots.com/en/latest/install.html#acceleration).
- **Flexible Datenverarbeitung:** Daten im Arbeitsspeicher und bedarfsgerechtes Laden aus HDF5-Dateien.
- **Hyperparameteroptimierung:** Modelloptimierung mit [Optuna](https://github.com/optuna/optuna).
- **Reproduzierbare Forschung:** Datensätze, Simulation fehlender Werte, standardisierte Vorverarbeitung und Evaluierungswerkzeuge im Ökosystem.
- **Erweiterbare Architektur:** Modulare Komponenten und standardisierte Vorlagen für die Integration neuer Algorithmen.

## ❖ Installation

PyPOTS benötigt Python 3.10 oder neuer und ist über [PyPI](https://pypi.org/project/pypots/) und [Anaconda](https://anaconda.org/conda-forge/pypots) verfügbar. Details zu Abhängigkeiten und Umgebung finden sich in der [Installationsanleitung](https://docs.pypots.com/en/latest/install.html).

Wähle entsprechend deiner Umgebung **eine** der folgenden Installationsmethoden. Die Aktualisierungsbefehle sind nur nötig, wenn PyPOTS bereits installiert ist.

**Option 1: pip (empfohlen)**

```bash
pip install pypots
# Zum Aktualisieren: pip install pypots --upgrade
```

**Option 2: Conda**

```bash
conda install conda-forge::pypots
# Zum Aktualisieren: conda update conda-forge::pypots
```

**Option 3: Docker**

```bash
docker run -it --name pypots wenjiedu/pypots
```

Drücke nacheinander Ctrl-P und Ctrl-Q, um die Verbindung zu trennen, ohne den Container zu stoppen. Mit `docker attach pypots` stellst du die Verbindung wieder her.

**Option 4: Aktueller Quellcode auf main (kann unveröffentlichte Änderungen enthalten)**

```bash
pip install https://github.com/WenjieDu/PyPOTS/archive/main.zip
```

## ❖ Verwendung

### Schnellstart

Dieses eigenständige SAITS-Imputationsbeispiel verwendet synthetische Daten und benötigt keinen Datensatz-Download. Die Eingaben haben die Form `(n_samples, n_steps, n_features)`, fehlende Werte werden als `NaN` dargestellt.

```python
import numpy as np
from pypots.imputation import SAITS

# Synthetische Zeitreihen mit fehlenden Werten erzeugen
rng = np.random.default_rng(42)
X = rng.normal(size=(16, 24, 8)).astype(np.float32)
X[rng.random(X.shape) < 0.1] = np.nan
train_X, test_X = X[:12], X[12:]

# SAITS-Imputationsmodell initialisieren
model = SAITS(
    n_steps=24, n_features=8,
    n_layers=2, d_model=64, n_heads=4,
    d_k=16, d_v=16, d_ffn=128,
    epochs=2, device="cpu",
)
# Modell trainieren
model.fit({"X": train_X})

# Testdaten imputieren
imputed_X = model.impute({"X": test_X})
print(imputed_X.shape)  # (4, 24, 8)
```

<summary><b>Beispiel zur Imputation auf PhysioNet2012 mit SAITS anzeigen:</b></summary>

``` python
import numpy as np
from pygrinder import calc_missing_rate
from benchpots.datasets import preprocess_physionet2012
data = preprocess_physionet2012(subset='set-a',rate=0.1) # Our ecosystem libs will automatically download and extract it
train_X, val_X, test_X = data["train_X"], data["val_X"], data["test_X"]
print(train_X.shape)  # (n_samples, n_steps, n_features)
print(val_X.shape)  # samples (n_samples) in train set and val set are different, but they have the same sequence len (n_steps) and feature dim (n_features)
print(f"We have {calc_missing_rate(train_X):.1%} values missing in train_X")
train_set = {"X": train_X}  # in training set, simply put the incomplete time series into it
val_set = {
    "X": val_X,
    "X_ori": data["val_X_ori"],  # in validation set, we need ground truth for evaluation and picking the best model checkpoint
}
test_set = {"X": test_X}  # in test set, only give the testing incomplete time series for model to impute
test_X_ori = data["test_X_ori"]  # test_X_ori bears ground truth for evaluation
indicating_mask = np.isnan(test_X) ^ np.isnan(test_X_ori)  # mask indicates the values that are missing in X but not in X_ori, i.e. where the gt values are

from pypots.imputation import SAITS  # import the model you want to use
from pypots.nn.functional import calc_mae
saits = SAITS(n_steps=train_X.shape[1], n_features=train_X.shape[2], n_layers=2, d_model=256, n_heads=4, d_k=64, d_v=64, d_ffn=128, dropout=0.1, epochs=5)
saits.fit(train_set, val_set)  # train the model on the dataset
imputation = saits.impute(test_set)  # impute the originally-missing values and artificially-missing values
mae = calc_mae(imputation, np.nan_to_num(test_X_ori), indicating_mask)  # calculate mean absolute error on the ground truth (artificially-missing values)
saits.save("save_it_here/saits_physionet2012.pypots")  # save the model for future use
saits.load("save_it_here/saits_physionet2012.pypots")  # reload the serialized model file for following imputation or training
```

## ❖ PyPOTS Ökosystem

Willkommen im Kaffeeuniversum von PyPOTS! Unser Ökosystem ist von der Kaffeezubereitung inspiriert: Jede Bibliothek übernimmt eine eigene Rolle in der Zeitreihenanalyse.

<a href="https://github.com/WenjieDu/TSDB">
    <img src="https://pypots.com/figs/pypots_logos/TSDB/logo_FFBG.svg" align="left" width="140" alt="TSDB logo"/>
</a>

👈 Zeitreihendatensätze sind unsere Kaffeebohnen, POTS-Datensätze sind unvollständige Bohnen. [Time Series Data Beans (TSDB)](https://github.com/WenjieDu/TSDB) erleichtert das Laden öffentlicher Zeitreihendatensätze. Die aktuelle Liste findest du im Repository.

<a href="https://github.com/WenjieDu/PyGrinder">
    <img src="https://pypots.com/figs/pypots_logos/PyGrinder/logo_FFBG.svg" align="right" width="140" alt="PyGrinder logo"/>
</a>

👉 [PyGrinder](https://github.com/WenjieDu/PyGrinder) mahlt die Bohnen, indem es fehlende Werte simuliert. Es unterstützt alle drei von Rubin[^13] definierten Ausfallmechanismen: MCAR (vollständig zufälliges Fehlen), MAR (zufälliges Fehlen) und MNAR (nicht zufälliges Fehlen). Simuliere fehlende Werte mit einer einzigen Codezeile.

## ❖ PyPOTS zitieren

PyPOTS wurde erstmals beim [MiLeTS-Workshop auf der KDD 2023](https://kdd-milets.github.io/milets2023/) vorgestellt. Wenn du PyPOTS in deiner Forschung nutzt, zitiere bitte den [Toolkit-Artikel](https://arxiv.org/abs/2305.18811v2).

```bibtex
@article{du2023pypots,
title = {{PyPOTS: A Python Toolkit for Data Mining on Partially-Observed Time Series}},
author = {Wenjie Du},
journal = {SIGKDD MiLeTS Workshop},
url = {https://arxiv.org/abs/2305.18811v1},
year = {2023},
}
```

```bibtex
@article{du2025pypots,
title = {{PyPOTS: A Python Toolkit for Machine Learning on Partially-Observed Time Series}},
author = {Wenjie Du and Yiyuan Yang and Linglong Qian and Jun Wang and Qingsong Wen},
journal = {arXiv preprint arXiv:2305.18811v2},
url = {https://arxiv.org/abs/2305.18811v2},
year = {2025},
}
```

Wissenschaftliche Projekte nutzen und zitieren PyPOTS. Entdecke [Forschung, die PyPOTS zitiert oder verwendet](https://scholar.google.com/scholar?as_ylo=2022&q=%E2%80%9CPyPOTS%E2%80%9D&hl=en).

### Verwandte Forschung

- **[SAITS](https://doi.org/10.1016/j.eswa.2023.119619)** (ESWA 2023, über 1.000 Zitationen): Das Forschungsprojekt, aus dem PyPOTS hervorging. Seine ursprüngliche Implementierung der Imputation mittels Self-Attention legte den Grundstein für die PyPOTS-Codebasis.
- **[TSI-Bench](https://arxiv.org/abs/2406.12747)** (arXiv-Preprint 2024): Standardisierter Benchmark zur Imputation von Zeitreihen mit 34.804 Experimenten, 28 Algorithmen und 8 Datensätzen unter vielfältigen Fehlwertbedingungen. Code-Repository: [Awesome_Imputation](https://github.com/WenjieDu/Awesome_Imputation).
- **[Deep Learning for Multivariate Time Series Imputation: A Survey](https://doi.org/10.24963/ijcai.2025/1187)** (IJCAI 2025): Taxonomie der Imputationsmethoden, Toolkits und Forschungsrichtungen.
- **[HELIX](https://openreview.net/forum?id=FN20iuPnEU)** (ICML 2026 Spotlight): Lernbare Identitäten und dimensionsübergreifende Synthese zur Zeitreihenimputation.
- **[End-to-End Learning for Partially-Observed Time Series with PyPOTS](https://doi.org/10.1145/3770855.3816470)** (KDD 2026 Hands-on-Tutorial): Praktische Abläufe von Datenaufbereitung und Multi-Task-Modellierung bis zur Evaluierung und Integration eigener Modelle. [Tutorial-Materialien](https://pypots.com/events/KDD2026Tutorial/).

## ❖ Mitwirken

Wir freuen uns über Beiträge von Forschenden, Entwicklerinnen und Entwicklern sowie Nutzenden:

- **Neue Modelle:** Beachte die [Aufnahmekriterien](https://docs.pypots.com/en/latest/faq.html#inclusion-criteria) und nutze eine aufgabenspezifische Vorlage (z. B. [Imputation](https://github.com/WenjieDu/PyPOTS/tree/main/pypots/imputation/template)).
- **Fehlerkorrekturen und Funktionen:** Melde reproduzierbare Probleme oder Verbesserungsvorschläge über [GitHub Issues](https://github.com/WenjieDu/PyPOTS/issues).
- **Dokumentation und Beispiele:** Verbessere Tutorials, API-Dokumentation, Beispiele und Übersetzungen.
- **Tests:** Ergänze Regressionstests zur Steigerung von Zuverlässigkeit und Reproduzierbarkeit.
- **Sicherheit:** Melde Schwachstellen vertraulich gemäß [SECURITY.md](https://github.com/WenjieDu/PyPOTS/blob/main/SECURITY.md).

Bevor du einen Pull Request einreichst, empfehlen wir dir, [pre-commit](https://pre-commit.com/) in deinem lokalen Klon zu aktivieren, damit deine Änderungen automatisch formatiert und geprüft werden:

```bash
pip install pre-commit
pre-commit install
```

Die Hooks werden bei jedem Commit automatisch ausgeführt. Wenn ein Hook Dateien ändert, überprüfe die Änderungen, füge sie erneut zum Staging-Bereich hinzu und wiederhole den Commit. GitHub CI prüft mit Ruff sowohl den Code als auch die Formatierung, selbst wenn du die Hooks nicht installierst. Weitere Informationen findest du im [Entwicklerleitfaden](https://docs.pypots.com/en/latest/dev_getting_started.html#using-pre-commit).

Mitwirkende werden auf der [GitHub-Seite der Mitwirkenden](https://github.com/WenjieDu/PyPOTS/graphs/contributors), der [PyPOTS-Website](https://pypots.com/about/#volunteer-developers) und gegebenenfalls in Release Notes gewürdigt. Bitte halte dich an den [Verhaltenskodex](https://github.com/WenjieDu/PyPOTS/blob/main/CODE_OF_CONDUCT.md).

Wenn PyPOTS hilfreich ist, gib dem Repository einen Stern, damit andere es leichter entdecken. Sieh dir auch die [Institutionen unserer Nutzenden](https://pypots.com/users/) an.
